# Prioritize state-rendered robot appearance

When a source provides synchronized qpos and the geometry, camera calibration, and robot pose needed for aligned rendering, its robot-only RGB is generated by the state renderer even if observed or predicted robot masks are also available. This prioritizes the same numeric-state-to-RAT path expected from future trajectory proposal modules and keeps robot appearance independent of full-RGB photometric augmentation.

## Consequences

State rendering occurs in a robot-only scene against black. Observed masks, predicted masks, scene depth, and scene geometry do not clip the rendered robot, because future occlusion and interaction belong to the semantic outcome GWM predicts rather than the proposed action representation. Masks may audit alignment or serve as an explicitly reported fallback only when a valid renderable state bundle is unavailable; they never silently override usable qpos. Robot-appearance provenance is fixed per source for a run, recorded in the manifest and checkpoint, and shown by the source visualization rather than mixed frame by frame.
